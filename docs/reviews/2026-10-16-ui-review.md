## 审计结论

**ACCEPT：需要围绕人的连续操作重组工作台。** 当前实现具备协议、领域操作与版本控制基础，但工作界面把设定、存储索引、协议和修订记录同时摊开，主要编辑操作却受挤压。“看素材 → 定位分镜 → 对照设定 → 编辑 → 确认保存”的连续路径尚未建立。

用户提出的资产预览、中央多标签页、大提示词编辑区、多分镜导航和品牌识别均有依据。另外确认了草稿丢失、撤销语义、清空提示词失败、新建设定失败、检查器显示错误主体等问题，优先级高于外观调整。

以下审计内容记录实施前的状态；后续实施结果见文末。评审阶段产物是评审与交互方案，没有修改应用实现或生产编排。线上修改仅限临时输入和界面切换；评审开始与结束显示的生产编排修订均为 **#11**。写入行为均在本地隔离的测试环境验证。

- **线上实测**：使用用户指定的 Browser 插件，经站点现有 GitHub SSO 进入工作台；查看网格、清单、拓扑、协议展开和协作面板；测试未保存输入切换镜头；检查未绑定主体的镜头。实际样本为 5 个镜头、1 个主体、1 个登记资产。
- **尺寸实测**：默认浏览器 `1280×720`，补充 `1440×900`。测量面板、输入框和媒体 DOM 元素，不把源码设想当作上线表现。
- **本地集成复现**：真实 React Workbench + client + Hono REST + domain，使用内存项目与测试身份；7 条临时缺陷复现检查。既有 19 条检查和新增 7 条复现检查合计 **26/26 通过**。复现检查通过表示缺陷可重复触发，不表示相应业务已正确实现。

- **边界**：未重新核验所有 Cloudflare 资源、部署提交映射及生产权限角色。本次浏览器登录成功不能替代这些验收。

### P3：识别与视觉整理

- 没有图形标识、favicon 和明确的品牌入口；左上“视频编排工作台”更像小状态标签。建议形成小尺寸可识别的标志 + `Video Compose` 字标，项目/编排名称另置于面包屑。
- 首屏把修订、分辨率、帧率、总帧数和协议入口放在很高的视觉层级；素材本体与未保存状态反而缺席。
- “不可变资产库（R2 SHA-256）”“DAG 拓扑”“Streamable HTTP”等实现名词不适合日常创作主界面。主界面使用“素材”“镜头关系”“协作”；技术细节在详情与接入设置查看。
- 多处小字、徽章和边框增加视觉噪声。选中状态、编辑状态、批准状态和素材状态应有不同职责，不靠大量装饰徽章表达。
- 当前“YAML / JSON 协议”入口实际上只展开 YAML；应明确提供格式切换、复制/下载，或把入口改为与实际能力一致的名称。

## 理想版本

### 以中央工作页承载主要任务

推荐固定的轻量镜头导航 + 中央工作内容，右侧只按需出现简短属性或审阅面板：

```text
标志 / Video Compose    项目 > 编排              当前保存状态 / 全局操作
────────────────────────────────────────────────────────────────────
镜头导航                分镜 | 素材 | 角色与道具 | 协作与历史
搜索 / 筛选             ────────────────────────────────────────────
镜头名称与缩略图         分镜总览 或 当前镜头工作页
上一镜 / 下一镜          真实素材预览 + 足够宽的提示词编辑
                        当前镜头绑定的设定、候选与已选素材
                        固定可达的保存 / 放弃草稿 / 恢复状态
```

这几个标签代表用户正在处理的内容；“网格 / 清单 / 依赖关系”是分镜内部的视图选项，不应和素材、设定或协作混成同一级切换。

选中镜头后在中央打开当前镜头工作页；保留上/下一镜和返回总览。需要同时对照素材时可以左右并排预览与编辑，但中等宽度应合并为同一个中央工作页，而不是把整个编辑器移到几屏之后。侧栏允许拖动宽度、真正收起并恢复空间；当前镜头、滚动位置与草稿不因切页丢失。

每镜头开一个长期保留的顶层标签会在 50/100 镜头时制造第二个导航问题。优先用固定内容页 + 镜头导航；若允许打开多个镜头标签，限制可见数量并提供关闭/溢出列表，草稿必须独立于标签是否挂载。

### 素材预览形成操作闭环

- 图片可见缩略图，能放大看完整构图；视频能播放和定位，音频能试听。显式显示加载、失败、无权限与无素材状态。
- 分镜总览优先展示选定输出或明确标注的候选/参考，不能把候选显示成已选定结果。仅有参考时写清“参考图”；没有素材时提供真实空状态。
- 角色和道具分别展示所引用的批准版本、变体及参考图集；镜头详情只展示当前镜头所绑定的内容。
- 人可以预览 → 对比候选 → 选用 → 读回修订结果。选用与批准均是明确的受权写入，不由预览自动触发。

**实施边界**：需要补齐项目受权的媒体读取契约，建议同源 Worker 内容路由，用稳定 asset ID 解析 R2 对象；读操作仍经过项目权限校验。音视频支持 Range/206 与按需读取，避免为了预览把整个大文件读入内存。浏览器用原生媒体能力播放已经存在的文件，不增加生成、转码、合成或发布运行时，也不把永久公开 R2 地址或临时签名 URL 写入协议。

### 提示词与保存

- 使用多行纯文本编辑器，画面提示词初始可见 8–12 行，可调高、可进入中央专注模式；支持中文、英文与多段落。普通 textarea 足以承载第一版，无证据前不引入重型代码编辑器。
- 每个草稿用项目/编排/镜头 ID 定位，保留编辑开始时的 baseRevision。切镜头/切标签保留草稿；刷新或离开时告知未提交内容。草稿保存与服务器修订提交明确区分。
- 每个镜头一个明确的保存作用范围，按钮显示“保存当前分镜”；显示修改中、提交中、已保存、提交失败/冲突。
- 明确支持清空字段。失败保留草稿；重试沿用同一操作幂等键；同字段冲突提供差异和处理入口，不能丢弃输入或用新 head 包装陈旧草稿强行提交。
- 若要自动提交服务器修订，需要先设计好冲突、节流和恢复行为。评审首选显式保存 + 草稿保留。

### 多分镜操作

- 先补镜头名/编号/提示词检索、跳转、上/下一镜、返回选中位置、状态筛选和批量选择。
- 新增/复制能明确选择插入位置；排序走稳定 ID 与相对锚点的领域操作，不使用数组位置当作长期身份。
- 批量修改在提交前显示范围与差异，失败原子回滚，避免部分成功却不提示。
- 总览支持合适密度、按需加载媒体；时间线在自己的横向视窗中滚动/缩放并自动定位选中镜头，页面本身不被撑宽。分镜操作多时保留关键编辑区与保存入口的可达性。
- 场景分组若需成为可导出语义，应单独审查协议设计；不能只在 UI 内建立第二份权威编排结构。

### 设定与协作

- 设定流程应为选择已有/上传参考 → 创建合法候选设定 → 修改及预览 → 明确批准 → 绑定确定版本与变体。按当前协议至少有一个参考资产；如果要支持无图草稿，需要明确的协议兼容决策，不能仅改 UI 绕过校验。
- “恢复某一历史版本”与“撤销我的编辑”分别命名。前者说明恢复整个编排和新建修订；后者需要真正的操作历史及多人编辑约束。
- 协作入口围绕改动差异、作者、对象、冲突、待审阅提案组织；MCP 接入参数移至设置。静态“已就绪”文案不能代替实际连接状态。

## 降级实现路径与交付顺序

这是依赖顺序，不是用工期或编码难度压缩目标：

1. **编辑行为修正**：U01–U05；按镜头保留草稿，统一保存范围，修复清空、恢复语义、设定创建和检查器范围。这些无需先重做视觉外壳。
2. **素材与主要布局**：受权媒体读取、图片/音视频预览、中央工作页、多行编辑与焦点管理。先让单镜头完整流程成立。
3. **规模与协作**：搜索/跳转/排序/批量、50/100 镜头验收、改动比较与审阅。实际性能证据决定是否需要列表虚拟化，不以缺证据虚构性能问题。
4. **品牌与细节**：标志、favicon、导航层级、术语、密度、图标和视觉一致性；可以同布局交付，不应取代前面的功能验证。

理想版本是图片/视频/音频和参考/候选/已选都可查看。若某种浏览器不支持源媒体编码，保留媒体元数据、明确不可播放原因和原文件下载，不能把该格式的预览标为通过；能够提供兼容文件时再补相应预览。不以“稍后再做”为由从范围静默移除音视频。

当前审计不建议引入新运行时、生成器、复杂编辑框架或协议重写。布局与草稿状态可以先在 adapter 层完成，保留领域层的权限、baseRevision、幂等键与不可变历史约束。若未来触及协议字段或数据迁移，需单列兼容与回滚决策。

## 机器验收面

现有验收矩阵中的“轻量工作台”主要由 jsdom 组件/接口检查证明；它没有浏览器布局、媒体解码、焦点导航和长列表体验的证据。应补真实浏览器验收，并在 `docs/roadmap.md` 对应业务行登记实际证据；尚未实现的交互不得因现有勾选而视为通过。

| 验收场景 | 可判定行为 | 对应矩阵能力 |
| --- | --- | --- |
| 当前镜头与草稿 | 两个镜头各写不同多段提示词，来回切镜头、切标签、展开/收起面板后分别保留；同一镜头的再次点击也不清空描述草稿。 | 轻量工作台 |
| 保存与失败恢复 | 清空提示词能读回空值；一个明确操作只提交声明的范围；网络失败/并发冲突保留输入；恢复网络后安全重试；重复点击/重试不产生重复业务操作。 | 轻量工作台 / 多 Agent 修订 |
| 恢复/撤销 | 用三个不同内容版本连续操作，验证与命名一致；恢复历史不改变既有历史快照，清楚说明影响范围；多人同字段修改不能静默覆盖。 | 多 Agent 修订与审阅 |
| 真实媒体 | 真实可解码的 PNG/JPEG、MP4、音频样本；图片加载与放大成功，视频播放/seek、音频播放可断言；坏文件/缺文件/不支持编码有可恢复错误。 | 不可变资产 / 轻量工作台 |
| 媒体权限 | reader/writer 可预览，非成员拒绝；reader 不能选用/上传/批准；不能复用另一项目的 asset ID 绕过授权。 | 不可变资产 / 角色与道具 |
| 设定 | 表单真实完成候选创建、参考预览、批准与绑定；无参考按协议在提交前提示；当前镜头无绑定时显示空态，其他镜头的主体不能混入；升级设定不改变旧镜头绑定。 | 角色/道具设定与参考图 |
| 桌面布局 | 1280×720、1440×900、1920×1080 截图与元素边界断言；选镜头后编辑区可达且不随镜头总表长度被推到末尾；收起面板确实增大主区；提示词可多行编辑。 | 轻量工作台 |
| 50/100 镜头 | 搜索最后一个镜头、上/下一镜、重排和批量修改；选中状态跨视图一致；页面无水平溢出；不为缩略图全量下载所有原视频。 | 轻量工作台 / 项目与编排 |
| 键盘与读写角色 | 只用键盘切镜头、切标签、编辑与保存；焦点位置可见；reader 看到清晰只读状态，writer 可写；越权仍由 API 拒绝。 | 轻量工作台 / HTTP-MCP |
| 项目导航 | 两个项目、每项目两个编排，列表切换与直达 URL 正确，跨项目后不残留上一项目草稿/素材；权限拒绝后有返回路径。 | 项目与编排 |

**人工验收**：小尺寸标志是否易认、分镜图是否能快速区分、视觉层级是否支持判断、提示词编辑是否舒适。这些需要人在真实素材和长提示词下验收，不能用截图存在或测试数量代替。

## 对照基线

仅把 input 改 textarea、增加折叠开关、换个 logo，可以缓解局部拥挤，但不能解决草稿丢失、媒体不可读、错误设定、恢复语义和长列表路径。它适合成为小改动，不足以作为本轮交互改进的完成标准。

## 自检

没有把问题归结为“深色不够美观”，也没有用更换 UI 库或重写协议逃避现有行为。没有因大规模体验缺少实测就宣称页面已经卡顿；规模风险与已复现缺陷分别列出。方案保持本项目的定义、协作、资产管理边界，未引入生成、渲染或发布能力。

## 本轮实施与验收（2026-10-16）

按用户“先改完再部署”的后续要求实施了主要交互改造：

- **U01 / U03 / U11**：按镜头保存当前页面草稿；切镜头、标签、视图和收起导航不丢输入。一个“保存当前分镜”操作提交已编辑字段，包括清空值。事务失败保留草稿及原幂等键；同字段冲突保留输入，显示服务器最新内容，明确重新核对后才能基于新修订提交。
- **U02**：改为会话局部撤销栈，逆向 Patch 只作用于本次编辑过的字段；检测竞争修改，保留其他人无关的字段。连续撤销不会在两份快照间来回切换。

- **U07 / U08 / U09 / U10**：中央标签与预览/编辑工作页、大多行提示词、专注模式、真实释放空间的导航收起、分镜检索/筛选/前后跳转/当前位置插入/稳定 ID 排序/批量选择与原子时长修改。镜头按钮和标签提供键盘语义，表单有明确标签。

## 项目管理入口补齐（2026-10-16 续）

U13 的项目/多编排导航已实现：主页 `/` 展示当前身份有权访问的项目，支持按名称/标识/简介搜索、新建项目；项目页展示编排列表及真实共享资源数量，可创建编排并设置规格/帧率；工作台提供返回项目与编排切换。每个项目和编排都有固定直达地址，支持复制、刷新及浏览器前进/后退。未知或无权访问的地址有返回入口，不再自动初始化猜测的目标。
